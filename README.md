# 数据关联分析台

从零实现的多目标数据关联工作台：输入只有**每帧带噪声的 2D 位置点**（漏检 + 杂点都存在），
输出轨迹、**保留歧义的多假设分支**、封存/更正账本，以及逐帧可回放的网页界面。

- 无第三方依赖：纯 Python 3.10+ 标准库（含手写 Hungarian / k-best / Kalman / 矩阵运算），
  前端是原生 HTML/CSS/JS。
- **只处理合成坐标**，不涉及摄像头或图像识别。真值只用于评估面板，追踪器看不到它。
- **从不声称全局最优**：`optimal_claim` 永远是 `false`，搜索截断单独用 `truncated_search` 报告。

![工作台结构](docs/structure.txt)

```
python3 app.py            # 打开 http://127.0.0.1:8765/
python3 -m unittest discover -s tests -v
python3 scripts/report.py # 终端里跑四种场景的贪心 vs 窗口对比
```

## 2. 关联代价（唯一的“评分”）

每条（轨迹 × 检测）配对都按同一公式打分，**越小越好**：

```
cost = NLL(z | 轨迹预测) − log(Pd) + log(clutter_density)
```

- `NLL`：卡尔曼新息的高斯负对数似然 `0.5·Δ² + 0.5·log(2π|S|)`。
- `−log(Pd)`：漏检惩罚的常数项，使“检测存在时关联它”总是优于忽略它。
- `+log(clutter_density)`：杂点的密度项。杂点密度取得很小，所以**“把检测当杂点”相当于 0 代价的参照**，
  只有预测明显更差时才会输给“杂点”。
- 门控：`Δ² > gate_chi2` 的配对不可行；未确认轨迹额外要求欧氏距离 `≤ init_gate_px`。
- 人工锁定：该配对代价再减去 `|lock_bonus|`（强先验，但仍可被报告为“越过门控”）。
- 漏检：每条轨迹有**独立的漏检列**（共享漏检列会导致“只能有一条轨迹漏检”），代价 `miss_cost`。
- 新生：每帧剩下来未关联的检测按“离所有预测最远优先”选至多 `birth_limit` 个建新轨迹，每个付 `birth_cost`。
  这是个明确写出的启发式，不是最优决策。

所有常数在 `TrackerConfig`（`tracker/engine.py`）里，网页“评估 → 搜索预算”可改。

## 3. 预测、门控、全局指派、生灭如何协同

1. **预测**：每条轨迹先做匀速卡尔曼预测。
2. **门控**：只有 `Δ²` 在 χ² 门内的配对进入代价矩阵；门控外仍会出现在审计表里，并写明原因。
3. **全局指派**：一帧的配对在**整帧范围**内用 Hungarian 求最小总代价，再在可行解上枚举前 `k_best` 个
   指派（Murty），而不是按最近距离逐对硬配。
4. **生灭**：指派后，未命中的轨迹累积漏检，超过 `max_misses` 死亡；未确认轨迹在 `init_window` 内
   攒够 M-of-N 命中才确认（`confirm_hits` / `confirm_window`），否则删除；未指派的检测可新生轨迹。
   这一步与本帧指派在同一个转移函数里完成，因此得到的是“本帧最优指派及其后续状态”，而不是先配对再补状态。

## 4. 窗口、假设树、分支与裁剪

`WindowedAssociator` 维护一棵假设树：

- 每帧从当前每个存活假设（beam 内的叶子）出发，枚举最多 `k_best` 个指派 → 子节点。
- 子节点的帧代价与“本帧最好”相差不超过 `branch_margin` 才成为新分支；否则只留最优子树。
- 所有子节点按**累计代价**排序，只保留 `beam_width` 个、且累计代价不落后最优超过 `prune_margin` 的。
- **每个被丢弃的假设都留档**：帧号、假设 key、相对最优的代价差 `gap`、父节点、原因
  （“超出 beam 宽度”或“累计代价差 > prune_margin”）。这是预算裁剪，不代表它一定更差。
- 帧 `f` 的数据到达后，推进封存线到 `f − window_len`；封存 = 在该帧的存活假设里选累计代价最小的
  （MAP）提交为该帧结论，其他假设的“结局”被快照（`committed` / `pruned` + 原因 + 代价差）。

**关于“最优”的诚实表述**：MAP 只是“当前 beam 内已评估假设中的最好者”。被裁剪的假设、beam 外的
假设、以及 Murty 预算之外的低代价指派都没有参与比较；`truncated_search` 只有在搜索**节点预算**
耗尽时为 `true`。界面底部与评估面板都重复这一点。

## 5. 迟到帧：两条路径

场景 `combined` 计划让第 24 帧晚 4 步送达（第 28 步）。

| 到达时…… | 行为 | 记录 |
|---|---|---|
| 该帧仍在开放窗口内（`frame > sealed_until`） | **回溯重放**：回滚到 `frame−1`，恢复祖先假设，插入迟到帧，再重放其后所有仍开放的帧 | `replays[]`：帧、送达步、封存线、回滚点、恢复的假设；时间轴上标紫色 |
| 该帧已被封存（`frame ≤ sealed_until`） | **只追加更正**：已封存关联一字不改，只追加“检测点被撤回 / 新增 / 整帧迟到”的关系记录 | `corrections[]`：类型、帧、检测点、封存线、说明；该帧标记 `sealed_kind = "late_correction"` |

测试覆盖两条路径（`tests/test_workbench.py::TestLateFrames`），并另外断言“更正不会改写已封存指派”。

## 6. 人工锁定与冲突

- 锁定 `(帧, 检测点, 轨迹)` 是**人工证据**：重建整个会话时作为该帧的强先验进入 assignment。
- 锁定后 `Session.rebuild()` **从第 0 帧重跑**，保证约束影响该帧之后的所有假设；把新旧结果 diff 成
  `revisions`（append-only 的重算记录：帧、之前、之后），不会静默改写历史。
- 追踪器是唯一裁决者，冲突带**具体检测点 id**：
  - `detection_claimed_twice`：同一检测点被锁定给多条轨迹 → 列出 `det_id` 与涉及的锁定；
  - `track_claimed_twice`：同一轨迹被锁定到多个检测点；
  - `lock_shadowed`：锁定与更早的锁定冲突而被遮蔽；
  - `lock_track_absent`：锁定引用的轨迹在该假设中不存在 → 指出 `det_id`；
  - 锁定一个不存在的检测点会直接被拒绝（`ok: false` + 错误信息）。
- 锁定不保证成立：越过门控的强关联会记一条 `outside_gate` 违反，而不是被悄悄接受。

## 7. 网页

`web/index.html` + `web/style.css` + `web/app.js`，零依赖：

- **画布**逐帧播放检测点、已确认/暂定轨迹、轨迹尾迹、人工锁定标记；可叠加真值（默认关）。
- **时间轴**区分已封存 / 窗口开放 / 迟到 / 重放 / 多假设帧；点击任意帧跳转；方向键与空格控制播放。
- **假设分支**：每个假设的代价、权重（softmax）、与 MAP 的指派差异、结局与原因；“查看由来”拉出
  该假设最近数帧的指派历史与子假设。
- **检测 / 排除原因**：点选画布或表格里的检测点，逐条列出它与每条轨迹的 Δ²、代价，以及“为什么没用”
  （门控外、轨迹选了更低代价的检测点、检测点被判给另一条轨迹、双方都未指派）。
- **锁定**：新增/解除，冲突列表（带检测点 id），锁定重算记录。
- **封存与更正**：封存线、挂起帧、重放、追加更正、被裁剪假设的评分表、迟到说明。
- **评估**：身份切换 IDSW、连续性、虚警轨迹、分支恢复、搜索预算、代价模型；可改预算并重算。
- **比较**：`对比` 弹窗并排显示同一场景/种子下贪心与窗口的全部指标；`导出 JSON` 下载逐帧原检测 + 关联结果。

配色：分类色只有 3 个验证过的槽位（蓝/橙/青），第 4 条及以后的已确认轨迹用**灰色虚线 + 轨道标签**
（颜色从不单独承载身份；所有面板都以文本 id 呈现）。

## 8. 四个场景与对照结果（默认种子）

| 场景 | 贪心 IDSW | 窗口 IDSW | 贪心虚警 | 窗口虚警 | 多假设帧（窗口） | 重放 |
|---|---|---|---|---|---|---|
| crossing 交叉相遇 | 0 | 0 | 0 | 0 | 2 | 0 |
| vanish 短暂消失 | **4** | **0** | 0 | 0 | 2 | 0 |
| clutter 高杂点 | 0 | 0 | **8** | **7** | 13 | 0 |
| combined 综合+迟到帧 | 0 | 0 | 1 | 1 | 22 | 1 |

- `vanish`：贪心在 A 消失期间把 B 的一段检测接到 A 的轨迹上，A 复现时只能新建轨迹（A/B 各 2 段、
  4 次身份切换）；窗口推断用 5 帧候补把歧义保留到 B 转向之后，A 恢复为单一轨迹。
- `crossing`：两目标在 19–22 帧最近距离 2.3 px。窗口在第 20/21 帧把“A/B 互换”的假设作为显式分支
  记录下来（权重约 9–10%，代价差约 2.2），最终选对后裁剪；贪心恰好也选对，所以 IDSW 同为 0。
- `clutter`：高频虚警下贪心靠最近距离会多养 1 条虚警轨迹；窗口多出 13 个“多假设帧”，把
  “两个检测点该给谁/新轨迹”的犹豫显式化。
- `combined`：第 24 帧迟到 → 回溯重放 1 次（窗口 8 帧）；若把窗口调到 2 帧，则改走“只追加更正”路径
  （测试里有断言）。

这些数字是**特定种子**下的结果；`scripts/report.py --seed N` 可换噪声抽样。种子扫描显示两种模式
并非处处分胜负：窗口在 IDSW/连续性上通常更好，但也会在个别种子上多出虚警或切换。这不是
“窗口必然更优”的结论，而是“窗口把歧义显式保留并可回看”的结论。

## 9. 局限（明确写出，不藏在注释里）

- **不是全局最优**，也不是任何意义下的 MAP——只是 beam 宽度和节点预算内的最好者。
- 运动模型只有匀速 + 白噪声加速度；没有机动检测、没有 IMM。
- 出生决策是启发式（最远优先 + 每帧上限），没有专门的新生假设检验。
- 确认是 M-of-N，没有完整的 track score/SPRT，虚警轨迹会残留（`clutter` 场景仍剩 7 条）。
- 所有参数（`Pd`、杂点密度、`miss_cost`、门控、确认规则）都是先验常数，不做自适应估计。
- 窗口内重放会重算其后所有开放帧；如果窗口开得很大、迟到很频繁，往返重放会变慢（复杂度随开放窗口
  的分支数增长）。
- 网页没有做像素级截图验证（环境无浏览器）；UI 由 `tests/headless_ui.mjs` 用最小假 DOM 驱动全部渲染
  路径与数据形状，图形本身仍需人工目测。
- 合成场景故意做小（100×100、40 帧、最多 4 个目标），用于说明机制，而不是性能基准。
